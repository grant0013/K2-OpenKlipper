# Desktop preview fixtures

These files travel with the repository. They contain synthetic UI data and
project-authored artwork, not a saved printer configuration.

- `cases/`: small JSON recipes naming a scenario, opening page and optional clicks.
- `assets/`: the example three-part print and printer illustrations, as SVG sources
  and ready-to-use PNGs. The shared printer SVG lives in `touchscreen/assets/printer.svg`
  and produces both CFS variants for the runtime and previews.

Run a case from the repository root:

```sh
sh touchscreen/developer-tools/preview.sh --case idle
sh touchscreen/developer-tools/preview.sh --case multi-cfs
sh touchscreen/developer-tools/preview.sh --case mesh
sh touchscreen/developer-tools/preview.sh --list
```

The launcher generates a current snapshot in a temporary directory and resolves
artwork paths for this checkout. It does not depend on a previous chat's outputs
or absolute paths from another PC. To save an editable full snapshot instead:

```sh
python3 touchscreen/developer-tools/demo_snapshot.py \
  touchscreen/out/preview/idle.json --case idle
```

## Add a case

Copy a JSON file in `cases/` and edit these fields:

| Field | Meaning |
| --- | --- |
| `description` | One-line explanation for `--list` |
| `scenario` | State generated by `demo_snapshot.py`; see `SCENARIOS` there |
| `page` | First native screen; `--page` can override it |
| `printer_image` | Artwork path relative to this `fixtures/` directory |
| `actions` | Optional native fixture actions, performed after opening the page |
| `model` | Optional display-only demo printer identity |
| `cfs` | Set to `false` for the no-CFS capability case |

`mesh.json` contains a measured surface and three profiles; `mesh-unloaded.json`
keeps the profiles but clears the active mesh, and `mesh-empty.json` has neither.
`meshing.json` replaces the surface with progress.

For example, `mapping.json` opens the selected file and runs `review_mapping`.
`wifi-password.json` selects a synthetic secured network to open its keyboard.
Actions use the same format as `tests/test_native_ui.py`; they never send printer
commands. `{"transport_lost": true}` simulates loss of the local touchscreen service. The recipes share the generator so changing the service snapshot schema
does not require maintaining many large JSON copies. For different status data,
add a scenario to `demo_snapshot.py`; keep recipes focused on artwork, pages and
action sequences.

Model names, temperatures, travel limits, IP addresses and spool records are
examples. They are not hardware profiles or configuration files to install.

## Rebuild artwork

After editing the SVG sources, regenerate and commit the corresponding PNGs:

```sh
python3 touchscreen/developer-tools/build_fixtures.py
```

This needs ImageMagick's `convert` with SVG support. PNGs are committed so normal
preview launches do not need to rasterize SVGs. The illustrations were drawn for the desktop preview; they do not use artwork
extracted from the printer firmware.
